# Krea manual and model routing
Read prompt-writing.md for Krea-native image authoring, image-references.md for supplied images/styles, parameters.md for a concrete checkpoint/provider, editing.md for actual modifications, examples.md and troubleshooting.md for practical cases.

“Krea” can mean the web platform, Krea 1, Krea 2 RAW/Turbo, Krea 3, FLUX.1-Krea-dev, or a community LoRA on another base model. Identify the existing model/template first. A Qwen model using a file named Krea LoRA is still a Qwen conditioning route unless its actual documentation says otherwise. Do not route every Krea request to the newest hosted model.

Local knowledge is detailed for Krea 2 prompting and RAW/Turbo inference, with separately labeled Krea hosted style-reference and Krea 3 edit profiles. FLUX.1-Krea-dev is covered as a distinct FLUX branch; do not reuse Krea 2 sampling. Krea-hosted third-party image/video models retain their own prompt and input contracts. Source status and API snapshots are local in sources.md and parameter-snapshot.json.
